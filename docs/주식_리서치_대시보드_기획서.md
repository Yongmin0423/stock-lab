# 주식 리서치 대시보드 기획서

> 개인 토이 프로젝트 · 작성일 2026-07-06 · 작성자 Yongmin

---

## 1. 프로젝트 개요

### 1.1 한 줄 정의
**"내 투자 공부가 AI의 판단 기준이 되는 개인 리서치 대시보드"**

책·영상에서 배운 투자 원칙을 노트로 기록하면, AI가 그 노트를 근거로 시장 데이터·재무·뉴스를 분석해 종목별 의견을 제시하는 웹 서비스.

### 1.2 핵심 차별점
- 일반 주식 앱: 데이터를 보여주고 판단은 사용자 몫
- 이 프로젝트: **사용자의 지식이 쌓일수록 AI 분석의 논리가 사용자 스타일로 진화**
- AI를 파인튜닝하는 게 아니라, 노트를 검색해 프롬프트에 주입하는 **RAG 방식** → 노트 하나만 추가해도 즉시 반영, 비용 거의 없음

### 1.3 설계 원칙
1. **혼자 만들고 혼자 쓴다** — 인증·멀티유저·과금 없음. 복잡도 최소화
2. **공부와 함께 성장** — 기능을 한 번에 다 만들지 않고, 공부 진도에 맞춰 계산식·노트를 추가
3. **무료 티어로 시작** — 모든 데이터 소스는 무료 API로 시작, 한도에 걸리면 그때 판단
4. **거래 기능 없음** — 추천/분석까지만. 매매는 증권사 앱에서 직접

## 2. 사용자 시나리오 (나의 하루)

> 포지셔닝: 실시간 시세는 증권사 앱의 영역. 이 서비스는 **하루 2번, 장 밖에서 생각하는 시간**을 담당.

1. **아침(개장 전)**: 폰으로 접속 → 간밤 미국 장 결과 + 오늘 한국 장 관전 포인트 확인 (MVP: 대시보드 / Phase 2: 아침 브리핑). 주목 종목이 있으면 상세에서 "AI 분석" 클릭
2. **저녁(마감 후)**: 오늘 한국 장 정리 + 마감 후 공시 + 오늘 밤 미국 관전 포인트 확인. AI 반론(⚠)이 달린 분석이 있으면 읽어보고, 필요하면 컨텍스트 복사해 외부 AI와 토론
3. **밤**: 『현명한 투자자』 읽다가 안전마진 개념 정리 → 지식 노트 작성, 태그 `가치투자` `안전마진`. 토론에서 교정된 내용이 있으면 노트 개정
4. **다음날**: 같은 종목을 다시 분석시키면 AI가 어제 쓴 노트를 인용하며 새 관점 반영 ← 핵심 체험

## 3. 기능 정의

### 3.1 MVP (Phase 1)

#### F1. Watchlist
- 종목 검색(티커/이름) → 관심종목 등록/삭제
- 카드형 목록: 현재가(15분 지연 허용), 등락률, 미니 스파크라인
- **미국 + 한국 주식 모두 지원**. 시장 구분 뱃지(US/KR), 통화별 가격 포맷($152.34 / 71,200원)
- 장 상태 표시: 한국(09:00~15:30 KST) / 미국(23:30~06:00 KST, 서머타임 22:30~) 장중·장마감 구분
- **빈 상태(첫 실행)**: 시총 상위 등 하드코딩 스타터 목록을 칩으로 노출 → 클릭 한 번에 추가 (콜드 스타트 해결, API 비용 0)

#### F2. 종목 상세
- 가격 차트 (일봉, 기간 선택 1M/3M/1Y)
- **기본 재무 지표 패널**: PER, PBR, EPS, ROE, 부채비율, 배당수익률, 시가총액, 52주 고저
- 재무제표 요약: 최근 4개년 매출/영업이익/순이익 추이 (막대 차트)
- 해당 종목 뉴스 목록

#### F3. 뉴스 피드
- watchlist 종목 관련 뉴스 통합 피드 (출처, 시각, 헤드라인, 원문 링크)
- 종목별 필터

#### F4. 지식 노트 (Knowledge Base)
- 마크다운 에디터로 노트 CRUD
- 필드: 제목, 본문, 태그(복수), 출처(책 제목/영상 링크), 작성일
- 태그·키워드 검색

#### F5. AI 분석 (핵심 기능)
- 종목 상세에서 "AI 분석" 버튼 → 아래를 하나의 컨텍스트로 묶어 Claude API 호출:
  1. 종목 기본 정보 + 재무 지표 (F2 데이터)
  2. 최근 뉴스 헤드라인 5~10건
  3. 관련 지식 노트 (태그/키워드 매칭, MVP는 단순 검색으로 충분)
  4. 사용자 정의 계산식 평가 결과 (F6)
- 출력 형식(구조화): 종합 의견(매수 검토/관망/회피) + 근거 3~5줄 + 인용한 노트 표시 + 리스크 요인 + **원칙에 대한 반론(challenges)**
- **반론 메커니즘 (잘못된 노트 방어)**: verdict은 내 원칙을 따르되, 원칙이 검증된 투자 지식과 상충하거나 오해·과잉일반화로 보이면 별도 섹션에 근거와 함께 이의 제기. 판단 권한은 사용자에게, AI는 반대 의견을 내는 스터디 파트너
- 분석 이력 저장 (나중에 "AI 의견이 맞았나" 복기용)

#### F6. 계산식 (스크리닝 룰)
- MVP: JSON 설정 파일로 하드코딩. 예시:
  ```json
  {
    "name": "저평가 우량주",
    "rules": [
      { "metric": "per", "op": "<", "value": 15 },
      { "metric": "debtToEquity", "op": "<", "value": 100 },
      { "metric": "roe", "op": ">", "value": 10 }
    ]
  }
  ```
- 각 룰의 통과/실패 여부를 종목 상세에 뱃지로 표시하고, AI 컨텍스트에도 포함

### 3.2 Phase 2

#### F7. 데일리 브리핑 (하루 2회) ← 이 서비스의 킬러 기능
- **아침(개장 전) / 저녁(장 마감 후)** cron으로 watchlist 전 종목 자동 분석 → **웹 브리핑 페이지** (`/briefing`)
- 전달 채널은 웹만으로 시작. 이메일·카카오톡 알림은 이후 확장 (브리핑이 DB에 저장되므로 채널 추가는 발송 레이어만 붙이면 됨)
- 접근성: 모바일 브라우저에서 아침에 바로 확인할 수 있도록 반응형 필수, 홈 화면 추가용 PWA 설정(manifest)은 저비용이라 함께 적용
- 구성: 종목별 요약·판단 변화 + **AI가 큐레이션한 연관 정보**
- 연관 정보 필터링 기준 = 하드코딩 아님. **내 지식 노트 + 과거 분석 이력** 기반으로 AI가 선별 (설계는 §5.5)
- 포지셔닝: 실시간 시세는 증권사 앱의 영역. 이 서비스는 "장 밖에서 생각하는 시간(아침/저녁)"을 담당

- 계산식 편집 UI (하드코딩 → 웹에서 생성/수정)
- 노트 임베딩 검색: 키워드 매칭 → 벡터 유사도 검색(pgvector)으로 업그레이드. "이 종목/뉴스와 관련된 노트"를 의미 기반으로 찾음 (브리핑 큐레이션의 기반이기도 함)
- 뉴스 AI 요약: 헤드라인 클릭 없이 3줄 요약
- **인기 종목 섹션**: 실데이터 기반 — 한국은 KIS 거래량·시가총액 순위 API, 미국은 FMP gainers/actives. 위치는 참고 정보로 한정(앱 철학은 원칙 기반이므로 중심에 두지 않음)
- **노트 AI 검토**: 노트 저장 시 "AI 검토" 버튼 — 사실 오류·개념 오해·과잉일반화·반례를 짚고 보완 제안. 검토 결과를 노트에 함께 저장해 "내 이해가 교정된 기록"으로 축적. 분석 시점 반론(F5)보다 근본적인 방어선 — 노트를 고치면 이후 모든 분석이 같이 교정됨
- **반론 컨텍스트 복사**: 앱 내 토론 기능은 만들지 않음(기존 AI 채팅의 재발명). 대신 반론(⚠) 옆 "컨텍스트 복사" 버튼 — 노트 원문+반론+관련 데이터를 마크다운으로 클립보드에 복사 → 아무 AI 채팅에 붙여 토론 → 결론이 나면 **수동으로 노트 개정**. 학습 루프(공부→노트→분석→반론→토론→개정)는 유지하되 토론만 외부에 위임

### 3.3 Phase 3
- **룰 기반 스크리닝 (진짜 "추천 종목")**: watchlist 밖에서 내 계산식을 통과하는 종목을 발굴. API 한도 때문에 범위 제한 — KOSPI200 + S&P500 구성종목을 주 1회 배치 스캔. "내 원칙에 맞는 종목 찾기" = 두 번째 킬러 기능 후보
- **추천 복기(백테스트 lite)**: 과거 AI 분석 시점 대비 현재 수익률 표시 → "내 원칙이 실제로 유효한가" 검증
- 노트 ↔ 종목 연결 그래프 (어떤 원칙이 어떤 종목 판단에 쓰였는지 시각화)
- 포트폴리오 수동 기록 (보유 종목/평단가 입력 → 평가손익)

### 3.4 명시적으로 안 만드는 것
- 실거래/주문 기능, 실시간 호가, 회원가입/멀티유저, 모바일 앱(반응형 웹으로 대체)

## 4. 데이터 소스 전략

### 4.1 미국 주식

| 데이터 | 소스 | 무료 한도 | 비고 |
|---|---|---|---|
| 시세/차트 | **Finnhub** | 60 calls/min | 실시간 US 시세, WebSocket도 가능 |
| 종목 뉴스 | **Finnhub** (company-news) | 동일 | 종목별 뉴스 기본 제공 |
| 기본 재무지표 | **Finnhub** (basic financials) | 동일 | PER, PBR, ROE 등 100+ 지표. 단 전체 재무제표는 유료 |
| 재무제표 (연간) | **FMP** (Financial Modeling Prep) | 250 calls/day | 손익/재무상태/현금흐름 5개년, 무료 티어로 충분 |

- 전략: **Finnhub 하나로 시작**(시세+뉴스+핵심지표 커버), 재무제표 추이가 필요해지면 FMP 추가
- yfinance는 비공식 스크래핑이라 차단·불안정 이슈가 있어 제외

### 4.2 한국 주식

| 데이터 | 소스 | 발급 절차 | 비고 |
|---|---|---|---|
| 시세 | **KIS 오픈API** (한국투자증권) | 계좌 필요 + 앱키 발급 | 아래 상세 |
| 시세 (대안) | 공공데이터포털 「금융위 주식시세정보」 | 이메일 가입 + 활용신청 | 전일 종가 기준. 일봉만 필요하면 계좌 없이 가능 |
| 재무제표 | **OpenDART** (금융감독원) | 이메일로 API 키 즉시 발급, 무료 | 상장사 재무제표/주요계정 조회. PER은 직접 계산(주가÷EPS) |
| 뉴스 | 네이버 검색 API (뉴스) | 네이버 개발자센터 앱 등록 | 종목명 검색으로 관련 뉴스 수집 |

**KIS API 발급 절차 (질문 주신 부분):**
1. 한국투자증권 **계좌 개설** (비대면 개설 가능, 이게 선행 조건)
2. KIS Developers(apiportal.koreainvestment.com) 접속 → 인증서 로그인 → 오픈API 이용 신청
3. 계좌번호 지정 후 신청 → **APP Key / APP Secret 발급** (승인 1~2일 소요될 수 있음)
4. 유효기간 1년, 만료 30일 전부터 갱신 가능 (갱신 시 키 재발급)
- 모의투자 계좌로도 신청 가능하므로 실계좌에 돈 안 넣어도 개발은 가능
- **전략**: 발급에 시간이 걸리므로 **1주차에 바로 신청**해두고, 승인 대기 동안 미국 파트를 먼저 개발. KIS가 지연되면 공공데이터포털 API(계좌 불필요, 전일 종가)로 임시 대체

### 4.3 한국 포함 시 설계 포인트 (미국과 다른 부분)

| 항목 | 미국 | 한국 | 대응 |
|---|---|---|---|
| 심볼 | `AAPL` | `005930` (6자리 코드) | `market` 필드로 구분, 내부 키는 `US:AAPL` / `KR:005930` 형태로 정규화 |
| 통화 | USD, 소수점 2자리 | KRW, 정수 | 통화별 포맷터 유틸 하나로 처리 |
| 지표 제공 | Finnhub이 PER/ROE 등 계산해서 줌 | OpenDART는 재무제표 원본만 | **PER = 주가 ÷ EPS 직접 계산** 레이어 필요 (§4.4) |
| 뉴스 | Finnhub 종목별 뉴스 | 네이버 뉴스 검색(종목명 쿼리) | 관련성 필터링 필요(동명 이슈), 제목에 종목명 포함 여부 등 휴리스틱 |
| 장 시간 | 23:30~06:00 KST | 09:00~15:30 KST | 시장별 개장 캘린더(휴장일 포함) 상수로 관리 |
| 기업 식별 | 티커로 통일 | DART는 고유번호(corp_code), KIS는 종목코드 | 종목코드↔corp_code 매핑 테이블(1회 다운로드) |

### 4.4 한국 재무지표 계산 파이프라인
OpenDART에서 재무제표(연간/분기) 수집 → EPS·BPS·부채비율 등 파생 지표 계산 → KIS 시세와 결합해 PER·PBR 산출 → `financials` 테이블에 저장. 지표 계산은 순수 함수로 분리해 단위 테스트 작성(공부한 재무 개념을 코드로 검증하는 재미 포인트).

- 지름길: 초기에 계산 로직이 부담스러우면 KIS 국내주식 기본시세 응답에 포함된 PER/PBR/EPS 필드를 우선 사용하고, DART 기반 자체 계산은 공부 진도에 맞춰 교체

### 4.5 API 한도 대응 (on-demand + TTL 캐시)
- 주기적 폴링 없음. **페이지를 열 때** 캐시가 오래됐으면 그 자리에서 갱신 (시세 2분, 재무 24시간, 뉴스 1시간 TTL) → 볼 때는 최신, 안 볼 때는 호출 0회
- cron은 딱 2가지만: 일봉 히스토리 적재(장 마감 후 1회), 데일리 브리핑(Phase 2, 하루 2회)
- 모든 외부 호출은 캐시 헬퍼를 경유 → 화면은 항상 DB 조회

### 4.6 지수·환율 (시장 상태 바용)

## 5. AI / RAG 설계

### 5.1 지식 노트 스키마
```
note {
  id, title, content(markdown),
  tags[],            // 예: ["가치투자", "안전마진"]
  source,            // 예: "현명한 투자자 20장"
  related_tickers[], // 선택: 특정 종목 관련 노트면 지정
  created_at, updated_at
}
```

### 5.2 검색 → 주입 파이프라인
- **MVP**: 태그 + 키워드 매칭(SQL LIKE / FTS). 노트 수십 개 수준에선 충분
- **Phase 2**: 노트 저장 시 임베딩 생성(예: Voyage/OpenAI embeddings) → pgvector에 저장 → 분석 요청 시 "종목 개요+뉴스 요약" 텍스트로 유사 노트 top-k 검색
- 주입 상한: 노트 5개 / 약 3,000 토큰. 넘으면 최신·유사도 순 우선

### 5.3 프롬프트 구조 (MVP 초안)
```
[시스템]
너는 나의 투자 스터디 파트너다. 아래 "나의 투자 원칙"을 최우선 판단 기준으로 삼아라.
원칙과 데이터가 충돌하면 그 충돌을 명시적으로 지적하라.
나의 원칙이 검증된 투자 지식과 상충하거나 오해·과잉일반화로 보이면,
verdict은 원칙대로 내리되 challenges에 근거와 함께 이의를 제기하라.
확정적 투자 조언이 아닌 학습용 분석임을 전제로 한다.

[나의 투자 원칙]  ← 검색된 노트들
- (노트 1: 제목 + 요지)
- (노트 2: ...)

[스크리닝 룰 평가 결과]
- 저평가 우량주: PER 12.3 (<15 ✅), 부채비율 140% (<100 ❌) → 미통과

[종목 데이터]
- AAPL, 현재가/PER/PBR/ROE/... , 최근 4년 실적 추이

[최근 뉴스]
- (헤드라인 5~10건)

[요청]
JSON으로 응답: { verdict: "매수검토|관망|회피", confidence, reasons[], cited_notes[], risks[], challenges[] }
```

### 5.4 분석 이력
```
analysis {
  id, ticker, verdict, confidence, reasons, cited_note_ids[],
  challenges[],        // 내 원칙에 대한 AI의 반론
  price_at_analysis,   // 복기용
  created_at
}
```

### 5.5 데일리 브리핑 & 연관 정보 큐레이션 (F7, Phase 2)

하루 2회 cron이 실행하는 파이프라인:

```
1. 수집     watchlist 종목의 시세 변화·새 뉴스·재무 업데이트
2. 1차 필터  뉴스 임베딩 ↔ 노트 임베딩 유사도로 후보 축소
            → 저렴한 모델(Haiku급)이 최종 선별:
            "이 사용자의 노트 태그와 과거 분석 이력에 비춰 볼 가치가 있는가?"
3. 변화 감지  직전 analyses와 비교해 델타 추출:
            - 판단 근거였던 지표가 바뀌었나 (부채비율 개선 등)
            - 회피/관망 사유에 새 뉴스가 붙었나
4. 생성     종목별 요약 + 큐레이션된 연관 정보
            + "왜 중요한지"(연결된 노트/과거 분석 명시)
```

**슬롯별 역할 정의 (겹침 방지)** — 가격만 정보가 아님. 한국 장이 닫힌 밤사이 미국 장 전체 + 공시 + 매크로가 움직임:

| 슬롯 (KST) | 정리 | 예고 |
|---|---|---|
| 저녁 ~16:30 | 오늘 한국 장 결과, 국내 뉴스, **마감 후 공시** | 오늘 밤 미국 장 관전 포인트 (실적 발표 예정 등) |
| 아침 ~08:00 | 간밤 미국 장 결과, 미국 뉴스, 매크로(Fed·환율·유가) | 오늘 한국 장 관전 포인트 |

- 델타 원칙: 직전 브리핑 이후 새로 생긴 것만 포함. 델타가 없으면 "특이사항 없음" 한 줄(또는 발송 스킵)
- 개장 후 시간대(예: 10시)로 옮기지 않음 — 시초가 반응 추적은 "장 밖에서 생각한다"는 포지셔닝과 충돌. 갭 등락은 저녁 브리핑이 정리

**주목 종목 섹션 (예측이 아닌 조건 충족 알림)**
- 단기 주가 예측은 하지 않음(신뢰성 없음). 대신 "지금 왜 이 종목을 봐야 하는지"를 근거와 함께 제시:
  - 룰 진입/이탈: "하락으로 '저평가 우량주' 룰에 처음 진입"
  - 판단 갱신 시점: "과거 관망 사유(실적 불확실성)의 해소 이벤트가 오늘 예정"
  - 원칙 관련 이벤트: 내 노트 주제와 연결된 뉴스·공시 발생
- 모든 항목에 근거 출처(룰/노트/과거 분석/이벤트) 필수 → 환각 방지 + 복기 가능
- 변화 감지가 가능한 이유: 모든 온디맨드/브리핑 분석이 `analyses`에 저장되기 때문. MVP 때부터 저장하는 이유
- 브리핑 결과도 `briefings` 테이블에 저장 (날짜, 아침/저녁 구분, 종목별 섹션, 큐레이션 항목과 선별 사유)

### 5.6 비용 추정
- 온디맨드 분석 1회 ≈ 입력 5K + 출력 1K 토큰 → Claude Sonnet 기준 회당 수십 원 수준
- 브리핑: 1차 필터는 Haiku급(회당 몇 원), 심층 분석은 watchlist 10종목 × 하루 2회 → 합쳐도 월 몇천 원대

## 8. 화면 구성 (7페이지)

### 8.1 대시보드 `/`

- 주목 종목 알림 (룰 진입/이탈 등)
- 최근 노트 3개

### 8.2 종목 상세 `/stock/[symbol]`
목적: 판단에 필요한 모든 근거를 한 화면에

- 헤더: 이름·코드·시장 뱃지·현재가·등락·장 상태
- 가격 차트 (1M/3M/1Y)
- 재무지표 패널: PER, PBR, EPS, ROE, 부채비율, 배당수익률, 시총, 52주 고저
- 4개년 실적 추이 (매출/영업이익/순이익 막대 차트)
- 룰 평가 결과 (통과/실패 + 각 항목 값)
- **AI 분석 버튼 + 결과 카드**: verdict, 근거, 인용 노트(클릭 시 노트로 이동), 리스크, 반론(⚠ 구분 표시 + 컨텍스트 복사 버튼)
- 탭: 뉴스 / 과거 분석 이력
- 이 종목 관련 내 노트 목록

### 8.3 지식 노트 `/notes`, `/notes/[id]`
목적: 이 서비스의 심장. 쓰기 편해야 쌓인다

- 목록: 태그 필터, 키워드 검색, 출처(책/영상) 표시
- 에디터: 마크다운, 제목·태그·출처·관련 종목(선택)
- **역링크**: "이 노트가 인용된 분석 N건" — 내 공부가 실제 판단에 쓰이는 걸 확인하는 재미 포인트

### 8.4 뉴스 `/news`
- 전 종목 통합 피드 (출처·시각·헤드라인·원문 링크)
- 종목/시장 필터, AI 큐레이션 항목 하이라이트 (Phase 2)

### 8.5 브리핑 `/briefing` (Phase 2)
- 아침/저녁 탭 + 날짜별 아카이브
- 구성 순서: 시장 요약 → 종목별 델타 → 주목 종목 카드 → 큐레이션 연관 정보(선별 사유 포함)

### 8.6 분석 이력 `/analyses`
- 전체 분석 타임라인, verdict·종목 필터

### 8.7 설정 `/settings`

## 10. 리스크 및 유의사항

- **API 무료 한도**: FMP 250 calls/day가 가장 빡빡 → 재무는 24h 캐싱 필수. Finnhub 60/min은 개인용으론 여유
- **무료 티어 정책 변경**: 데이터 소스가 Provider 인터페이스 뒤에 있으므로 교체 비용 낮게 유지
- **AI 환각**: 반드시 "제공된 데이터/노트만 근거로" 지시 + 근거 인용 강제(cited_notes). 수치는 AI가 생성하지 않고 DB 값을 그대로 표시
- **법적 성격**: 본인만 쓰는 학습 도구지만, 화면에 "투자 조언 아님" 문구를 넣어두는 습관 권장. 공개 배포 시엔 별도 검토 필요
- **노트 유실 방지**: 노트는 이 서비스의 유일한 대체 불가 자산 (시세·뉴스는 다시 받으면 됨). ① 노트 markdown 일괄 export 기능을 MVP 직후 최우선 추가 ② Supabase 무료 티어는 **일정 기간 미사용 시 프로젝트 일시정지**되므로 주의 (브리핑 cron이 생기면 자연 해소)
- **번아웃 방지**: MVP 범위(§3.1)를 절대 늘리지 말 것. "이것도 넣을까?"는 전부 Phase 2 백로그로

> 단, §11.4의 "지금 해둘 것 2가지"만은 현재 개발에 반영.

### 11.1 기술
- 인증 + 멀티테넌시: 전 테이블 `user_id` + Postgres RLS. Supabase Auth 사용 시 전환 비용 낮음
- **데이터 원가가 최대 이슈**: 무료 API 한도는 유저 10명이면 소진 → 유료 데이터 계약 필요. 같은 종목은 유저 수 무관 1회만 fetch하는 **공유 캐시**가 원가 방어의 핵심
- AI 비용: 유저당 브리핑 2회/일 → 구독제 없이는 적자 구조. 분석 횟수 티어링
- 브리핑 배치가 유저별 큐 작업으로 확장 → 큐 시스템(예: pg-boss, Inngest) 필요

### 11.2 법률/규제 (한국) — 최대 허들
- 불특정 다수에게 투자 판단(verdict) 제시 → **유사투자자문업 신고** 대상 가능성. 개인 맞춤 조언으로 해석되면 투자자문업 라이선스 영역
- 이 서비스는 "사용자 자신의 원칙을 실행하는 도구" 구조라 프레이밍상 유리하나, 서비스화 시점에 **법률 전문가 검토 필수**
- 시세 데이터 재배포: KRX 데이터·KIS API·Finnhub 무료 티어 모두 제3자 제공엔 별도 라이선스 필요
- 면책 조항, 이용약관, 개인정보처리방침 (노트 = 개인 투자관, 민감 데이터)

### 11.3 프로덕트
- 차별화: 기존 앱은 "모두에게 같은 분석", 이건 "**내 공부만큼 똑똑해지는 분석**"
- **콜드 스타트**: 신규 유저는 노트 0개 = 핵심 가치 체험 불가 → 온보딩에서 원칙 템플릿(가치투자 스타터팩 등) 제공 or 질문 몇 개로 초기 노트 생성
- 노트/계산식 공유 마켓 → 네트워크 효과의 씨앗
- 복기 기능(분석 성적 투명 공개)이 신뢰의 근간
- **반론 토론 스레드 (인앱)**: 혼자 쓸 땐 외부 AI 채팅으로 충분하지만, 서비스라면 앱 안에서 토론이 완결돼야 함. 설계안: 컨텍스트 고정형 스레드(노트+반론+분석) → 출구는 항상 노트 개정 제안 → 수락 시 노트 업데이트 + 개정 이력 저장

### 11.4 지금 해둘 것 (딱 2가지)
1. 스키마 설계 시 `user_id` 컬럼이 들어갈 자리를 의식해둘 것 (지금 넣진 않아도 됨)
2. 외부 데이터 fetch를 "종목 기준 공유 캐시" 구조로 짤 것 — 어차피 혼자 쓸 때도 §4.5 캐싱과 동일한 구조
