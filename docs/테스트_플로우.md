# 테스트 플로우

> MVP 기능을 사용자 동선 순서대로 검증. 15~20분 소요.
> 전제: DATABASE_URL + FINNHUB_API_KEY + ANTHROPIC_API_KEY 설정 완료.

## 0. 환경 확인
- [ ] `pnpm dev` 실행 → localhost:3000 접속
- [ ] "모의 데이터 모드" 배너가 **없어야** 함 (있으면 키/재시작 확인)

## 1. Watchlist (M2)
- [ ] 빈 상태에서 스타터 칩 "+ Apple" 클릭 → 카드 생성, 실제 가격 표시
- [ ] ⌘K → "TSLA" 검색 → 추가 → 카드 등장
- [ ] 같은 종목 재검색 시 "추가됨 ✓" 표시
- [ ] 카드 hover → ✕ 클릭 → 제거됨
- [ ] 새로고침 + 서버 재시작 후에도 목록 유지 (DB 저장 확인)
- [ ] 미국 장 상태 표시가 현재 시각과 맞는지 (23:30~06:00 KST = 거래 중)

## 2. 종목 상세 (M3)
- [ ] 카드의 종목명 클릭 → 상세 페이지 이동
- [ ] 캔들 차트 렌더링 + 1M/3M/1Y 토글 동작 (토글은 API 재호출 없이 빨라야 정상 — DB 캐시)
- [ ] 재무지표 8종에 값 표시 (일부 "—"는 정상, 전부 "—"면 이상)
- [ ] 스크리닝 룰 카드: ✓/✗ 와 지표별 값이 재무지표 패널과 일치하는지 ← **수치 정합성 체크**

## 3. 뉴스 (M5)
- [ ] 상세 페이지 하단에 해당 종목 뉴스 표시, 클릭 시 원문 새 탭
- [ ] /news 통합 피드 + 종목 필터 칩 동작
- [ ] 페이지 재방문 시 빠르게 뜨는지 (1시간 캐시 = DB 조회)

## 4. 지식 노트 (M6)
- [ ] 새 노트 작성: 제목/본문(마크다운)/태그/출처/관련종목(US:AAPL) 저장
- [ ] 미리보기 토글에서 마크다운 렌더링 확인
- [ ] 태그 칩 필터, 키워드 검색 동작
- [ ] 관련종목 지정한 노트가 그 종목 상세의 "관련 노트"에 골드 카드로 표시

## 5. ★ AI 분석 — 핵심 루프 (M7)
이 앱의 존재 이유. 순서대로:

- [ ] **5-1**: 노트가 있는 종목에서 "✦ AI 분석 실행" → 결과 카드 (verdict/근거/리스크)
- [ ] **5-2**: 근거에 `[note-N]` 인용 칩이 있고, 클릭하면 해당 노트로 이동
- [ ] **5-3**: 근거 속 수치(PER 등)가 화면의 재무지표와 일치 ← **환각 체크, 샘플 2~3종목**
- [ ] **5-4**: 노트 내용을 반대 방향으로 수정 (예: "PER 15 이하만" → "성장주는 PER 무시")
- [ ] **5-5**: 같은 종목 재분석 → **결과/근거가 달라졌는지** ← MVP DoD의 핵심
- [ ] **5-6**: 일부러 틀린 원칙의 노트 작성 (예: "PER이 낮으면 무조건 저평가") → 재분석 → ⚠ 반론 섹션에 이의 제기가 뜨는지
- [ ] **5-7**: 분석 여러 번 실행 → 이력이 아래에 쌓이는지, 새로고침 후에도 최신 분석 표시

## 6. 장애/엣지 동작
- [ ] .env.local에서 FINNHUB_API_KEY 잠시 제거 + 재시작 → 모의 데이터 배너, 앱은 정상 동작
- [ ] 노트 0개 상태에서 AI 분석 → "등록된 원칙 없음" 명시하고 일반 분석 (죽지 않아야)
- [ ] 뉴스 없는 종목 → "아직 뉴스가 없어요" 표시

## 7. 자동 테스트 (선택, 1세션)
순수 함수만 vitest로 — UI 테스트는 혼자 쓰는 규모에선 과함:

```bash
pnpm add -D vitest
```
- `src/lib/rules.test.ts`: 경계값 (PER 정확히 15, 값 undefined, 룰 전부 통과/실패)
- `src/lib/format.test.ts`: KRW/USD 포맷, 시총 단위(T/B, 조/억)
- `src/lib/market-hours.test.ts`: 주말, 장 시작/끝 경계, 서머타임 날짜
