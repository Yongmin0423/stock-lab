# 브리핑 개선 1차: 이전 판단과 수치 비교

## 구현 범위

수동 생성과 Cron이 공유하는 `generateBriefing`에서 직전 브리핑 본문·주목 항목을 읽고, 현재 데이터와 이전 수치 스냅샷을 비교한다. 계산 결과와 자료 경고를 기존 AI 작성 단계에 전달한다.

```text
Next.js: 시세·재무·뉴스·룰·노트 수집
  → 현재 스냅샷 생성 + 직전 브리핑의 스냅샷 조회
  → Worker POST /briefing/compare: 수치·룰 변화 계산
  → Next.js: 비교 결과 + 직전 본문·확인 과제 + 현재 자료로 AI 작성
  → 출력 종목 검증
  → Supabase: 본문·현재 스냅샷·비교 결과 함께 저장
```

## 저장과 기존 기록 호환

- 기존 `briefings.stock_sections` JSON 배열의 각 종목에 선택적 `snapshot`·`comparison`을 추가한다. 컬럼 추가나 DB 마이그레이션은 없다.
- 스냅샷에는 시세 기준 시각·모의 여부·재무 조회 시각·6개 지표·룰 조건과 평가 결과를 저장한다. 노트 원문은 스냅샷에 포함하지 않는다.
- 기존 기록은 본문을 그대로 표시한다. 스냅샷이 없는 기록이나 새 관심종목은 비교 기준 없음으로 처리한다.
- 첫 개선 브리핑은 기준선을 저장한다. 이후 생성부터 수치 비교가 가능하다. 직전 기록의 본문과 확인 과제는 스냅샷이 없어도 참고할 수 있다.

## 계산과 작성 규칙

- 당일 등락률과 직전 스냅샷 대비 가격 변화율을 구분한다.
- 가격 변화율은 양쪽 모두 실데이터이고 시세 기준 시각이 더 최신일 때만 계산한다. 누락·모의·동일/과거 시각이면 비교를 보류한다.
- 재무 변화는 조회 시각이 더 최신이고 양쪽 수치가 있을 때만 계산한다. 이는 조회된 지표의 차이이며 새 공시나 실적 개선 자체를 입증하지 않는다.
- 룰 조건이 같고 갱신된 재무 자료로 평가됐을 때만 진입·이탈을 표시한다. 자료 부족은 미통과가 아닌 평가 불가로 구분한다. 같은 이름의 룰이 여러 개면 비교에서 제외한다.
- 시세가 수집 시각보다 72시간 이상 오래되면 경고한다. 이는 초기 표시 기준이며 거래일별 신선도 판정은 후속 개선이다.
- AI에는 직전 본문·주목 항목, 비교 결과·경고, 현재 근거와 뉴스 URL을 전달한다. 이전 AI 해석을 사실로 간주하지 않고, 확인할 새 근거가 없으면 확인 불가로 작성하도록 한다.
- 출력 종목 누락·중복·미등록 종목, 주목 종목 3개 초과·중복은 저장 전에 거부한다. 자연어 해석의 사실성 전체를 자동 검증하는 기능은 아직 아니다.
- 브리핑 화면의 ‘수치 비교·자료 상태’를 펼치면 코드로 계산한 수치와 경고를 확인할 수 있다.

## Worker 연결 설정

```dotenv
RESEARCH_BRIEFING_COMPARE_MODE=worker
```

- 기본값은 `local`이다. 명시적으로 `worker`를 선택하면 `/briefing/compare`를 호출한다. Worker 장애 시 자동으로 다른 경로를 실행하지 않고 생성 실패로 표시한다.
- Worker에는 전·현 수치 스냅샷만 전송한다. 브리핑 본문·노트·모델 API 키는 보내지 않는다.
- 요청 본문 SHA-256 해시·경로·시각·요청 ID를 HMAC으로 서명한다. 본문 변조·만료 요청을 거부한다. 순수 계산 API이며 DB 쓰기·LLM 호출·작업 생성이 없어 유효 시간 내 재전송은 같은 계산을 반복할 뿐이다.
- 입력은 512KB, 응답은 256KB, 전·현 종목은 각각 최대 100개로 제한한다. 요청 제한 시간은 10초다.
- 2026-11-02에 Worker 버전 `0c45af25-e988-448e-a5a7-ed1b77ebfef0`를 배포하고 가상 수치로 실제 HTTP 비교를 검증했다. 로컬 모드는 `worker`로 설정했다.
- Vercel에는 앱 코드와 Worker 주소·시크릿·비교 모드를 별도로 배포해야 한다. 로컬 환경 변수를 바꿨다면 서버 재시작이 필요하다.

## 검증과 다음 단계

```bash
pnpm test:briefing
pnpm test:research
pnpm test:research:runtime
pnpm worker:typecheck
pnpm worker:dry-run
pnpm build
```

실제 운영 브리핑 생성·유료 모델 호출·DB 저장은 이번 검증에서 실행하지 않았다. 고정된 가상 자료로 비교, 기존 기록 호환, 본문 서명, Worker 왕복, 과거 확인 과제의 AI 입력 포함, 잘못된 출력 거부를 검사했다. 실제 결과의 유용성은 생성 후 검토해야 한다.

현재 우선 목표는 기존 자료의 분석 품질이다. 작성 프롬프트는 핵심 해석을 먼저 제시하고 시장·재무·룰·뉴스·투자 원칙을 연결해 지지 근거와 반대 근거, 시점 차이와 자료 한계를 검토하도록 수정했다. 다음 확인은 해석을 바꿀 조건이 있을 때만 짧게 쓰도록 했다. 모델·호출 횟수·토큰 예산은 변경하지 않았다. 이 수정의 실제 유용성은 동일 자료로 생성한 결과를 비교해 평가해야 한다.

자동 추가 조사·서브 에이전트·Workflows 비동기 생성·DO 대화 저장은 현재 우선 구현 범위가 아니다.
